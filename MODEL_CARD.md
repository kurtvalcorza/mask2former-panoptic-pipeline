#### Description

`facebook/mask2former-swin-tiny-coco-panoptic` is the Transformers-format release of Mask2Former with a Swin-T backbone trained on COCO panoptic segmentation, from "Masked-attention Mask Transformer for Universal Image Segmentation" (Cheng, Misra, Schwing, Kirillov, Girdhar; arXiv:2112.01527, CVPR 2022), released by Facebook AI Research and pinned here to revision `df6b1142ff50c3276559d9d78f35f6a579c75a77` (the Hub's `main` on 2026-09-18). The snapshot `config.json` declares `Mask2FormerForUniversalSegmentation`: a Swin-T backbone (embedding dimension 96, depths 2/2/6/2, 3/6/12/24 heads, window 7, four output stages), a pixel decoder with a 6-layer multi-scale deformable-attention encoder (feed-forward 1024) producing 256-channel mask features at stride 4, and a 10-layer masked-attention transformer decoder (hidden size 256, 8 heads, feed-forward 2048) over 100 learned object queries — about 47.4M parameters in the 190 MB float32 `model.safetensors`. Each query yields a distribution over 133 COCO panoptic categories (80 things, 53 stuff) plus *no object* and a 96×96 mask logit map. The upstream loss (Hungarian matching; class cross-entropy weight 2.0, point-sampled mask BCE 5.0 and dice 5.0 over 12,544 sampled points, no-object weight 0.1, auxiliary decoder losses) is carried by the pinned `transformers` implementation and is what this repository's `finetune` calls. At inference the processor (`Mask2FormerImageProcessor`, `preprocessor_config.json`: 384×384 resize without preserving aspect ratio, ImageNet mean/std, `ignore_index` 255) encodes the image once; this package then applies the upstream panoptic rule itself in NumPy and Pillow — score-thresholded queries, score-weighted per-pixel argmax, a per-pixel mask threshold below which a pixel is **void**, an overlap threshold that drops queries that lost most of their mask, stuff fusion — because the pinned `transformers` post-processor assigns every pixel to the argmax query and hands a whole out-of-domain image to a single weak query (recorded in the smoke run). What this repository adds is packaging: `verify_snapshot` and `stage_missing_files` (manifest digest checking and fresh-clone staging), `Mask2FormerPanopticPipeline.from_pretrained` (verified local loading with `trust_remote_code=False`, optional re-headed class vocabulary with a seeded head initialisation), `segment` (input validation, panoptic map and segment list at input resolution, backend output checks), `panoptic_from_logits`, `panoptic_quality`, `mask_bbox`, the `validate_inputs` and `evaluation_report` stage helpers, the drawn samples (`synthetic_scene`, `shape_dataset`) with `validate_dataset`, `split_records`, `load_labelled_dir`, and the bounded adaptation path `finetune` / `evaluate` / `save_artifact` / `load_artifact`.

#### Intended Use and Limitations

The uses below are the ones the package was built to support; everything else is either out of scope (§Out-of-scope use cases) or prohibited (§Use cases).

###### Primary Intended Uses

The task is panoptic segmentation: input one image (`PIL.Image.Image`, any mode, converted to RGB) and three thresholds; output an int32 map at input resolution assigning every pixel to one segment id or to void (`-1`), plus one entry per segment (label, class index, thing/stuff, score, area fraction, tight box, fused flag). Envisioned applications are scene parsing for photographs of everyday environments (COCO's vocabulary: people, vehicles, animals, furniture, food, and stuff regions such as sky, road, wall, grass), region proposals for annotation tools where a person refines the map, coarse coverage or count estimates for COCO categories across an image collection, and — through the adaptation path — a starting point for a small panoptic vocabulary of the operator's own on their own labelled scenes, with the held-out panoptic quality they measure deciding whether it is good enough. Within DIMER the pipeline is an inference component and a bounded adaptation baseline, not a certified segmenter for any domain.

###### Primary Intended Users

Intended users are machine-learning engineers, computer-vision developers, annotation-tool builders and researchers integrating panoptic segmentation into research prototypes or in-house tooling. A user is expected to understand that a segment's score is an *uncalibrated softmax* over a query's class distribution — 0.9 is not a 90 % chance the label is right — that the three post-processing thresholds are theirs to choose and change what is kept and what is void, that the map is a hard assignment (one segment or none per pixel; stuff regions are fused per class, things are separate instances), that every image is resized to 384×384 so boundaries are soft and objects smaller than a few of the 4-pixel mask cells vanish, that the model was trained on COCO photographs so drawings, documents, medical and aerial imagery are distribution shifts on which a confident label carries no signal, that the adaptation path replaces the COCO vocabulary entirely (the re-headed model knows only the classes it was given), that a held-out panoptic quality on drawn shapes is plumbing evidence and not a benchmark, and that segmentation quality can only be measured on panoptic annotations they supply. Users who need calibrated confidence, sharp boundaries, open-vocabulary labels, or the ADE20K / Cityscapes checkpoints of the family are expected to know none of that is provided here.

###### Out-of-scope use cases

1. **Capability boundary:** no calibrated confidence, no abstention beyond the score threshold (a blank image was labelled `sky-other-merged` at 0.80), no vocabulary other than COCO's 133 categories at inference (the adaptation path substitutes, it does not extend), no boundary refinement beyond bilinear resampling of a 96×96 mask map, no batching across images, no mixed precision, and — in `finetune` — no backbone training by default, no hyperparameter search and no data augmentation.
2. **Input boundary:** `segment` rejects non-PIL images (`TypeError`), sides below `MIN_IMAGE_SIDE = 16` px or above `MAX_IMAGE_SIDE = 4096` px, and thresholds outside `[0, 1]` (`ValueError`). Every image is resized to 384×384 without preserving aspect ratio, so thin panoramas are squashed and small objects are unlikely to be segmented. `finetune` and `evaluate` reject (through `validate_dataset`) records without an id, image, instance map and instance→class mapping, instance maps that leave a pixel unassigned or disagree with the mapping, ids outside 1..254, more than 50 instances per image, more than 200 records, vocabularies outside 2..32 distinct names, epochs outside 1..20, batch sizes outside 1..8 and learning rates outside (0, 1].
3. **Input boundary:** the checkpoint's training data is COCO panoptic — photographs of everyday scenes with 133 categories. Flat drawings (the tutorial's shapes), documents, charts, medical, microscopy and satellite imagery fall outside what the upstream authors evaluated and what this repository measured; results on them are undefined, not merely degraded. The adaptation path was measured only on drawn scenes of five classes; how a real dataset of the operator's would adapt is not measured here.
4. **Decision boundary:** not for autonomous decisions that act on the map — automated cropping, redaction, measurement of areas or counts for safety, clinical, agricultural or industrial decisions, content moderation, robotics, or surveillance — without a human checking the map, and a locally measured panoptic quality on the deployment's own annotated images at the chosen thresholds.

#### Factors

###### Groups

This pipeline is human-centric whenever a `person` is in the image: COCO's `person` class is the most frequent thing category in the training data, and the model will segment people in any photograph; neither the upstream authors nor this repository audited mask quality, boundary accuracy or false negatives by depicted group (skin tone, age, dress, mobility aids, group size), and the tutorial photograph contains no people. Non-human groups whose accuracy is unknown, not known to be equal: non-photographic images (the tutorial's drawn shapes, where the model kept one region as `stop sign` and left the rest void), non-Western objects, food, clothing and scenes, low-light and low-resolution captures, crowded scenes with many small instances, and any category outside COCO's 133. An operator whose images contain people is responsible for a fairness audit on their own image set, stratified by depicted group, before relying on the output (see §Use cases).

###### Instrumentation

The upstream "instruments" are the COCO photographs (Flickr images captured with consumer cameras, annotated with polygons and stuff masks by crowd workers). Inference images arrive from whatever produced them — a phone camera, a scanner, a render, a drawing library — and resolution, exposure, colour balance, compression and aspect ratio all change the visual evidence; the fixed 384×384 resize discards aspect ratio and detail regardless of the source, so a 4096×4096 input carries no more information than a 384×384 one, and the resampled map inherits the 96-pixel mask grid's softness. The pipeline validates type, size and thresholds only; it cannot detect an unusual capture or a non-photographic image. The synthetic samples (flat Pillow shapes, no texture or lighting) are themselves a rendering instrument unlike any COCO photograph, which is why their panoptic-quality numbers are sanity evidence rather than a measurement; the public photograph is the checkpoint's own model-card widget example, fetched over plain HTTP and refused unless its SHA-256 matches the pinned digest.

###### Environment

Operating environment: Python 3.12 with `torch==2.14.0`, `torchvision==0.29.0`, `torchaudio==2.11.0`, `transformers==4.57.6`, `safetensors==0.8.0`, `numpy==2.5.3`, `pillow==11.3.0`, float32 on CPU; CUDA is used automatically when visible (float32) but was not exercised for this card. Measured on the reference machine with the GPU hidden (`CUDA_VISIBLE_DEVICES=-1`) and the Hub offline (`HF_HUB_OFFLINE=1`): load 18.0 s cold (the same snapshot loaded in well under a second once cached by the OS); `segment` on 640×480 images 1.7–8.2 s in the smoke run (0.5 s in the pre-flight kernel), the difference being the NumPy/Pillow per-query resampling and CPU contention, not the decoder pass (0.4–0.7 s); re-heading 0.5 s; `evaluate` on six 320×240 scenes 3.4–5.8 s; the 54-step fine-tune 185 s (about 3.4 s per step at 384×384, batch 2); `save_artifact` 0.4 s and `load_artifact` 0.2 s for the 190 MB directory. Data environment: the model assumes a COCO-like photograph; the drawn samples violate that assumption on purpose and the checkpoint behaved accordingly (one `stop sign` on the disc, void elsewhere), while the adaptation path turns those drawings into the model's whole world. Photographs of the operator's domain, crowded scenes and small objects are where this repository did not measure, and the pipeline reports no signal when they occur.

#### Metrics

###### Performance Measures

At inference the pipeline reports no accuracy measure: a segment's score is an uncalibrated softmax and the map is the fixed post-processing rule's output; `area_fraction`, `bbox` and `void_fraction` describe the map, not its quality. The repository ships the field's own measure because it is what a caller would use to evaluate: `panoptic_quality(pairs, class_agnostic=False)` implements Kirillov et al.'s PQ — segments matched at IoU > 0.5 (unique by construction), `SQ` the mean IoU of matches, `RQ = TP / (TP + FP/2 + FN/2)`, `PQ = SQ × RQ`, per class and averaged over classes with thing/stuff aggregates, reference void ignored — and the public `evaluation_report(result, reference=None)` stage returns, when a reference map is supplied, `pq`, `sq`, `rq` and the match counts with the verdict `sample-sanity` (class-agnostic by default, because the COCO vocabulary does not name drawn regions), or the verdict `not-measurable` naming the annotations that would be required. `evaluate(records)` reports class-aware PQ over labelled records through the same `segment` call as inference. PQ over COCO panoptic val2017 is the conventional measure (the upstream paper reports PQ for this configuration); it needs COCO's annotations, which are not bundled, and neither the upstream number nor any COCO measurement is reproduced or claimed by this pipeline. The adaptation tutorial reports PQ on six held-out drawn scenes beside two baselines — the re-headed model before training and a trivial all-`sky` predictor — as adaptation evidence, not as a benchmark.

###### Decision thresholds

The model has no decision of its own: it emits, per query, a class distribution and a mask logit map. The decision parameters are three caller-owned thresholds, exposed on `segment`, `validate_inputs` and `evaluate` and recorded in every result and report: `score_threshold` (default `SCORE_THRESHOLD = 0.5`, the pinned `transformers` default; the upstream Mask2Former panoptic inference uses 0.8) gates queries on their best class probability; `mask_threshold` (default `MASK_THRESHOLD = 0.5`) is the per-pixel cut below which a pixel stays void; `overlap_threshold` (default `OVERLAP_THRESHOLD = 0.8`, the upstream value) drops a query whose assigned area is below that fraction of its thresholded mask. On the drawn scene the smoke run kept one segment at 0.5 and 0.3 (`stop sign`, 0.601) and none at 0.8; on the photograph 0.5 and 0.8 kept the same five segments (void 4.9 % and 2.8 %). The `finetune` hyperparameters (learning rate 1e-4, weight decay 0.05, batch 2, 6 epochs, `TRAIN_NUM_POINTS = 4096`, backbone frozen, seed 0) are explicit defaults chosen for a practical CPU runtime, not tuned; the held-out PQ is reported, never used to select anything. A deployment owns the thresholds and the vocabulary, and decides how a map is verified before it is used.

###### Approaches to uncertainty and variability

This repository reports no central metric value for the COCO task and therefore no dispersion: the smoke run records timings, the segments of a few images and one class-agnostic PQ on one drawn scene. For the adaptation path it records one seeded run — PQ 0.866 on six held-out scenes (SQ 0.938, RQ 0.911; stuff 0.999, things 0.777: `sky` 0.999, `ground` 0.999, `disc` 0.841, `triangle` 0.981, `box` 0.509) from a re-headed baseline of 0.0 and a trivial all-`sky` baseline of 0.103, plus PQ 0.952 on four new-seed scenes — with no confidence interval; the fresh local kernel reproduced the held-out 0.866 exactly. Run-to-run variability at inference comes only from floating-point kernel selection across CPU builds and accelerators (no sampling, no seed); the drawn scenes use no text rendering, so their bytes do not depend on the Pillow build. In adaptation the head initialisation and the epoch shuffles are seeded, so a fixed seed on fixed hardware is repeatable, but a different seed or a CUDA device changes the head's start and can move the held-out PQ by an amount this repository did not measure. A caller who needs an accuracy estimate must supply panoptic annotations and compute PQ over many images or seeds themselves at their chosen thresholds; a caller who needs a confidence per segment has none from this model.

###### Mitigations

- **Supply-chain integrity:** `MODEL_REVISION` is a 40-hex commit; `stage_missing_files` refuses a manifest whose `modelId`/`revision` differ from the package constants and fetches only manifest-listed files at that revision when `allow_download=True`; `verify_snapshot` then checks all 4 listed files' byte sizes and SHA-256 before any load; `from_pretrained` loads only from the verified directory with `local_files_only=True`, always passes `trust_remote_code=False`, and the smoke run loaded, segmented and fine-tuned with `HF_HUB_OFFLINE=1`. The upstream `pytorch_model.bin` (pickle) is neither listed nor loaded. `load_artifact` refuses a foreign format, a different base identity or a file whose digest differs from the artifact manifest before importing model libraries. A test flips one hex digit of a manifest digest and asserts the loader refuses; another asserts a foreign manifest is refused; the import-boundary tests assert that a missing or tampered snapshot, and a tampered artifact, are refused before `torch` or `transformers` is imported.
- **Input integrity:** the public `validate_inputs` stage applies exactly the checks `segment` applies (both route through one shared private checker) and returns an input manifest recording the schema, the observed input, the thresholds and the verdict; `validate_dataset` applies exactly the ceilings `finetune` and `evaluate` apply and returns a dataset manifest with per-class instance counts, a dataset digest and findings (an unused class); `segment` raises when the backend returns logits of the wrong shape; the tutorial's public photograph is refused when its digest differs from the pinned value; the BYOD archive cell refuses members that would escape the target directory and extracts member by member.
- **Reproducibility:** exact `==` pins in `pyproject.toml`; deterministic post-processing; seeded head initialisation, split and epoch shuffles; every result carries `model_id`, `model_revision`, the thresholds, the vocabulary and the image size; the artifact manifest carries the base identity, the training record, the head seed and every file's digest.
- **Refusals:** no batching across images, no download without the explicit flag, no Hub access at inference or training time, no pickle deserialisation, no `extractall`, no attempt to guess whether an image is a photograph, and no filtering of image content — that policy is the operator's to implement around the pipeline.
- No statistical mitigation (class balancing, subsampling) is applied in `finetune`; a class with no instances is reported as a finding and left unlearned.

###### Risks and harms

- **Confident nonsense out of domain:** the model has no abstention beyond the score threshold — a blank white image was labelled `sky-other-merged` at 0.80 over its whole area and uniform noise at 0.57 over 95 % of it; downstream consumers that trust a map (editors, redaction, measurement) inherit the error silently.
- **Threshold dependence:** the same image yields more or fewer segments and more or less void as the three thresholds move (one segment at 0.5, none at 0.8 on the drawn scene); a deployment that never tunes them on annotated images ships an arbitrary trade-off.
- **Segmenting people:** COCO's `person` class makes the model segment people in any photograph, with unaudited accuracy by group; surveillance and profiling uses are prohibited below.
- **Soft, coarse boundaries:** the 96×96 mask grid blurs edges and drops small objects; a map used for measurement carries that error.
- **Catastrophic forgetting by design:** the adaptation path replaces the class head, so the adapted artifact knows only the new vocabulary; an operator who expects COCO categories to survive will get none.
- **Automation bias:** a clean-looking map, or a held-out PQ near 0.9 on drawn shapes, invites trust that neither an uncalibrated softmax nor a six-scene sample has earned.
- **Bias amplification:** any image population COCO under-represents (non-Western scenes, specialised domains) is reproduced as uneven map quality, undetected because no per-group evaluation exists.
- **Resource use:** a 190 MB model, 0.5–8 s per image on the reference CPU, about 3 minutes of CPU for the default fine-tune, and a 190 MB artifact per adaptation; the CUDA path was not measured.

###### Use cases

Prohibited even where the model would work: segmenting images of people to identify, track, profile or surveil individuals, or to infer protected characteristics; processing images or adapting on datasets the operator has no right to process, including intimate imagery and licence-restricted material; presenting maps or panoptic-quality figures as verified measurements, evidence or benchmark results without human review; deceptive editing that presents automatically segmented, removed or replaced content as authentic; and any use that violates the upstream weight licence terms, the COCO terms, the DIMER deployment terms, or the consent and data-protection obligations attached to the images processed. Autonomous high-consequence actions triggered by unreviewed maps are prohibited by the intended-use contract above.

## Input/output contract

- `Mask2FormerPanopticPipeline.from_pretrained(device=None, weights_dir=None, allow_download=False, *, class_names=None, stuff_names=(), seed=0, train_num_points=4096)` — stages missing manifest files (only with `allow_download=True`), verifies digests, loads; with `class_names` rebuilds the class head for that vocabulary (`stuff_names` marks the amorphous classes); `device` defaults to `cuda:0` when visible, else `cpu`; float32 on both.
- `segment(image, *, score_threshold=0.5, overlap_threshold=0.8, mask_threshold=0.5) -> dict` with keys `segmentation` (int32 `(H, W)`, segment id or `-1`), `segments` (per segment: `id`, `label`, `label_id`, `is_thing`, `score`, `query`, `was_fused`, `area_fraction`, `bbox` xyxy or `None`), `void_fraction`, `width`, `height`, the three thresholds, `class_names`, `adapted`, `model_id`, `model_revision`.
- `finetune(records, *, epochs=6, batch_size=2, learning_rate=1e-4, weight_decay=0.05, seed=0, freeze_backbone=True, freeze_pixel_decoder=False, progress=None) -> dict` (the run record: adaptation, loss, optimizer, hyperparameters, trainable/total parameters, per-epoch history, dataset digest); `evaluate(records, *, thresholds) -> dict` (class-aware `panoptic_quality` plus per-image counts); `save_artifact(path, *, notes="") -> dict`; `load_artifact(path, device=None) -> Mask2FormerPanopticPipeline`.

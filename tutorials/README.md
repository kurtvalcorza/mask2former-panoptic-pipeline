## Conformance notes

- **Standalone carrier (ST1–ST6), both notebooks:** the primary path performs no clone, repository install, or repository import. Section 2 carries `src/mask2former_panoptic_pipeline/samples.py` then `pipeline.py` verbatim (one cell each, tagged `metadata.dimer.embedded_module`, in dependency order; the only rewrites make the default weights directory working-directory-relative and remove the package-relative `from .samples import` line), Section 3 carries the model identity and the 4-file SHA-256 manifest inline and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins. `metadata.dimer.generated_from` records the repository, the generating revision, the modules' SHA-256, and the generator version.
- **Parity (PAR1–PAR3):** `tests/test_notebook_parity.py`, `tests/test_finetune_parity.py` and `tools/validate_release_assets.py` fail when a carried module, the inline manifest, or the inline pins differ from the repository, or when a notebook is not byte-identical to the generator's output.
- **Model acquisition:** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent (on a fresh runtime all four: `README.md`, `config.json`, `preprocessor_config.json`, the 190 MB `model.safetensors`), from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes every entry; `from_pretrained(weights_dir=WEIGHTS_DIR)` hands the verified directory to `AutoImageProcessor` / `Mask2FormerForUniversalSegmentation` with `trust_remote_code=False` (the Mask2Former implementation is the pinned `transformers==4.57.6` one; no model-repository code runs). The `E2E` notebook builds its re-headed pipeline from the same already-verified `WEIGHTS_DIR` with no second download and no Hub call after Section 3.
- **Public photograph (`TASK-INFERENCE`, Section 7):** the one input that is not drawn in code is fetched over plain HTTP from `images.cocodataset.org` (the checkpoint's own model-card widget example) and refused unless its SHA-256 equals the pinned digest (ST6: explicit, reproducible, documented host); it is display and inference only, has no reference map, and can be switched off with `FETCH_PUBLIC_PHOTO = False`. Its Flickr licence is not verified by this repository.
- **Role stages:** `validate_inputs` writes `outputs/mask2former_panoptic_input_manifest.json` with the schema, ceilings, the observed input, the thresholds, the verdict, and one recorded rejection finding (a `score_threshold` outside `[0, 1]`); `evaluation_report` writes `outputs/mask2former_panoptic_evaluation_report.json` — `sample-sanity` with class-agnostic `pq` / `sq` / `rq` and match counts on the drawn scene, `not-measurable` (with what annotations would make the task measurable) on the photograph and on BYOD. In the `E2E` notebook `validate_dataset` writes the dataset manifest (with one recorded rejection: an unassigned pixel), `evaluate` provides class-aware panoptic quality before and after adaptation, and the evaluation report records the trivial and re-headed baselines beside the adapted score (EVAL10, EVAL5: one seeded holdout, no dispersion estimate).
- **Adaptation (FT1–FT8, ART1–ART8, VER1–VER5):** the fine-tune runs in the kernel with explicit hyperparameters and states what is frozen; the loss history is labelled optimisation evidence only; the artifact is the full adapted model in the format DIMER serving consumes, with a manifest naming the base identity, vocabulary, head seed, training record and per-file digests; reload goes through `load_artifact` from the directory alone and the notebook asserts identical held-out PQ and pixel-identical maps, then proves a tampered manifest is refused.
- **Known 2.0 caveats, stated in the notebooks:** the drawn samples are plumbing evidence, not a benchmark; one seed and one split, no dispersion estimate; the pinned processor configuration carries a `_max_size` key the pinned `transformers` warns about at load (ignored); the public photograph is fetched over HTTP (digest-pinned).
- `USE_BYOD`, `USE_BYOD_IMAGE` and `USE_BYOD_DATASET` default to `False` so the sample paths never open an upload dialog.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the
  clean-runtime execution requirement; a release review must confirm that a recorded clean run in
  `docs/release-verification.md` matches the notebook revision under review before the status is
  promoted to `Release-grade`.
